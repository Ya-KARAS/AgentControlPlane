# AgentControlPlane v0.9.3

This is a local-first, single-user public test release, not a certified release.
ACP and Browser Companion are version 0.9.3. Web Bridge remains 0.9.6; its
standalone files and immutable historical artifacts are unchanged.

## Changes

- Fix automatic reroute classification. Only an explicit `passed` result, or an
  explicit `not_run` result whose detail has no failure wording and no nonzero
  exit code, is benign. Unproven test entries, negated pass wording, plural
  `Tests` or `Builds` failure summaries, a missing status, and nonzero exit
  status stay `task_failure` under quota and rate-limit errors. The shipped
  default stays off. Existing configurations that set
  `executor.reroute.enabled=true` are not changed. The feature remains
  experimental and is not a supported acceptance gate.
- CI publishes an aggregate check named `test` that fails unless every matrix
  job succeeds. The per-platform checks remain `test (ubuntu-latest)` and
  `test (windows-latest)`.
- README, README.zh-CN, and the release checklist describe the fixed
  classifier. The [v0.9.1](v0.9.1.md) and [v0.9.2](v0.9.2.md) notes still
  record the defect as it stood in those releases.
- Since v0.9.2, each workspace keeps a persistent thread per executor.
  `handoff_project` sends a terminal task's bounded continuation package to
  another executor in the same logical lineage without replaying the source
  thread. `fresh_session: true` starts an independent session and leaves the
  saved thread in place.

## Verification boundary

Linux Node.js 22.23.4 `npm run verify` on this release commit passed
627 tests, skipped 1, and failed 0. The static check passed.
These results are the code regression gate. They do not establish native
Windows installation or upgrade, real browser dispatch, real-provider
execution, or complete runtime isolation. GitHub CI on the release pull
request is the Ubuntu and Windows automated gate. No live model call is part
of this publication.

Automatic reroute remains experimental, off by default, and outside the
supported validated feature set. The classifier defect described in the
previous public test releases is fixed here. This release does not certify
native installation/upgrade, general Unicode shell use, macOS, or live
providers.

## Upgrade and rollback

1. Stop the selected ACP instance. Preserve the old installation and privately
   back up local config, environment, state, browser pairing and workspaces.
   Respect any configured state-directory override. Never upload those backups.
2. Extract 0.9.3 beside the old version. Use its lockfile with `npm ci`; do not
   copy old dependencies or overwrite personal configuration with defaults.
3. Run `npm run verify`, `npm run demo -- --help` and the passive
   `npm run demo -- --check --executor <your-executor>`. On Windows use
   `npm.cmd` where necessary. Passive checks do not verify authentication.
4. Run only one version against a state directory. Older builds ignore the new
   mutex protocol and must not share that directory concurrently. A stale lock
   requires operator review; do not delete it to force a dispatch.
5. Load the new Companion directory if desired, preserving existing settings.
   Keep automatic reroute disabled unless an existing local config already
   opts in. Keep DSH disabled until its profile, authentication and live tests
   are ready.

To roll back, stop 0.9.3 and privately preserve new evidence/workspace edits.
Switch to the retained 0.9.2 installation with its matching pre-upgrade config
and state snapshot. Do not assume newer state is backward-compatible or replace
current project edits with old backups. Keep the old release/tag/assets intact.

License, provider neutrality, loopback defaults and existing private configs
are unchanged. Each selected executor uses its own permissions and quota.
