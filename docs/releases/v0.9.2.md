# AgentControlPlane v0.9.2

This is a local-first, single-user public test release, not a certified release.
ACP and Browser Companion are version 0.9.2. Web Bridge remains 0.9.6; its
standalone files and immutable historical artifacts are unchanged.

## Changes

- Add an optional native DSH CLI executor, disabled by default and excluded
  from automatic routing. Existing executor IDs, routing and default config
  remain unchanged. No authentication or active DSH profile is shipped.
- Bind the native runtime/profile contract, process ownership and exact tool
  receipts. Unknown execution outcomes refuse automatic replay. Report unknown
  usage and unverified capabilities explicitly.
- Add opt-in TaskStore checkpoints with bounded retention, strict identity
  checks and retained dispatch idempotency. All current state writers now use
  a shared transaction mutex and reject stale snapshots.

See [DSH integration](../DSH-INTEGRATION.md) and
[recovery limits](../DSH-RECOVERY-DESIGN.md) before considering an opt-in profile.
The encoding compatibility contract covers a fixed ASCII command only.
`persistentThreads:false`, `hardInterrupt:false` and `runtimeVerified:false`
remain accurate. Windows read-only ACLs do not establish read/network isolation.

## Verification boundary

Windows code verification passed 573 tests without model calls. The backend PR
and its main merge also passed Linux Node 22 CI: 572 passed, one Windows-only
test skipped, zero failures. These results establish the code regression gate,
not real DSH or browser end-to-end acceptance.

Zero-model native component checks exercised the installed Job runner and
bounded read-only ASCII compatibility path. No real authenticated DSH Agent
task, native restart continuation, or ChatGPT/DeepSeek webpage to original-chat
ACP_RESULT roundtrip has passed acceptance. Those real-use tests await user
feedback and separate authentication/model-cost approval where required.
No new model request is part of this publication.

Automatic reroute remains experimental, off by default and outside the supported
validated feature set. Its known classifier defect described in the
[previous release](v0.9.1.md) remains. This release does not certify native
installation/upgrade, general Unicode shell use, macOS, or live providers.

## Upgrade and rollback

1. Stop the selected ACP instance. Preserve the old installation and privately
   back up local config, environment, state, browser pairing and workspaces.
   Respect any configured state-directory override. Never upload those backups.
2. Extract 0.9.2 beside the old version. Use its lockfile with `npm ci`; do not
   copy old dependencies or overwrite personal configuration with defaults.
3. Run `npm run verify`, `npm run demo -- --help` and the passive
   `npm run demo -- --check --executor <your-executor>`. On Windows use
   `npm.cmd` where necessary. Passive checks do not verify authentication.
4. Run only one version against a state directory. Older builds ignore the new
   mutex protocol and must not share that directory concurrently. A stale lock
   requires operator review; do not delete it to force a dispatch.
5. Load the new Companion directory if desired, preserving existing settings.
   Keep DSH disabled until its profile, authentication and live tests are ready.

To roll back, stop 0.9.2 and privately preserve new evidence/workspace edits.
Switch to the retained 0.9.1 installation with its matching pre-upgrade config
and state snapshot. Do not assume newer state is backward-compatible or replace
current project edits with old backups. Keep the old release/tag/assets intact.

License, provider neutrality, loopback defaults and existing private configs
are unchanged. Each selected executor uses its own permissions and quota.
