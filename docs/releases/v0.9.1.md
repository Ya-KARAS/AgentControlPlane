# AgentControlPlane v0.9.1

This is a local-first, single-user public test release, not a certified release.
The ACP package and browser companion are version 0.9.1; the separately versioned
Web Bridge userscript is 0.9.6.

## Changes

- Preserve structured context, constraints, acceptance criteria, and required
  evidence across the web handoff, candidate review, and executor prompt.
- Preserve task continuation and executor/session identity when following up;
  explicit compatible executor changes retain the logical task lineage.
- Provide portable demo CLI output and a passive `demo --check` preflight. The
  preflight does not dispatch a task, call a provider, use model quota, or write
  runtime, state, or workspace files. It does not establish authentication or
  live model availability.
- Normalize execution reports through a shared contract and fail closed on
  malformed, incomplete, contradictory, or failed test evidence rather than
  treating it as successful completion.
- Isolate development userscript builds from the stable update artifacts. This
  release explicitly promotes the integrated source to Web Bridge 0.9.6 while
  preserving all earlier versioned artifacts, including development artifacts.

## Dependency and request validation hardening

The dependency refresh uses MCP SDK `^1.32.1` and its updated lockfile to address
`GHSA-46jr-4wx8-v453`. MCP tool-input validation is bounded to 10,000 elements,
alongside the existing 1 MiB HTTP JSON body limit. These are bounded request checks,
not a claim that all denial-of-service or security risks have been eliminated.
The refreshed dependency tree reported zero production vulnerabilities in
`npm audit --omit=dev` at preparation time; advisory results can change.

## Verification boundary

The exact source ZIP was extracted into clean directories and installed with
`npm ci` on Linux using Node.js 22.19.0 and 24.19.0. On each runtime,
`npm run verify` passed: 481 tests, 480 passed, one Windows-only test skipped,
and zero failures; syntax, generated-artifact freshness, documentation links,
and browser-companion consistency checks also passed. Three package builds
(two on Node 22 and one on Node 24) produced byte-identical ZIPs.

Passive preflight, repeated Linux start/stop with a loopback metadata-only
fixture, and synthetic upgrade-preservation checks also passed. No model was
executed. These automated checks are not native-platform or end-to-end
certification; the skipped Windows test is not a passing Windows result.

Native Windows installation and upgrade, macOS operation, real-browser dispatch,
and real-provider execution have not been manually verified for this release.
The maintainer will perform the manual tests separately. No new live model call
or paid-provider test is represented by these release notes. Run only the manual
checks you intend to authorize; live demo execution can use model quota.

Automatic reroute remains experimental, opt-in, and outside this release's
supported and validated feature set. Its known classifier defect can allow
nonempty test evidence, including `passed` or `not_run`, to mask an infrastructure
failure and prevent rerouting. The shipped default remains off; an existing
configuration that explicitly enables it is not silently changed.

### Source release versus portal deployment

At release preparation, the existing stable auto-update endpoint at
`https://acp.asterroute.com/downloads/agent-control-plane-web-bridge.meta.js`
still serves Web Bridge 0.9.5. Packaging 0.9.6 or manually installing its GitHub
release file does not deploy it to the portal or update existing installations.
The configured stable download and update URLs are unchanged. Portal deployment
is a separate operation through the portal's existing release process and must
be verified independently before claiming its auto-update channel is current.

## Upgrade without losing local data

1. Stop ACP and any existing background startup task before changing versions.
   Keep the installed v0.9.0 directory intact. Do not run both versions against
   the same listening port or state directory at the same time.
2. Back up `config/local.json`, any local `.env`, the actual state directory,
   browser pairing/settings, and all workspaces or uncommitted project files.
   Respect `AGENT_CONTROL_STATE_DIR` when set. The default state location is
   `%LOCALAPPDATA%\AgentControlPlane\state` on Windows, or
   `${XDG_STATE_HOME:-$HOME/.local/state}/agent-control-plane` on macOS/Linux.
   Keep these backups private; they may contain credentials or task data.
3. Extract v0.9.1 beside v0.9.0, not over it. Use the new package and lockfile;
   do not reuse or copy the old `node_modules` directory. Copy your local
   configuration privately into the new installation, preserving executor,
   workspace, provider, and state settings. Do not replace it with example
   defaults, erase existing state, or move project workspaces into the source.
4. In the new directory run `npm ci`, `npm run verify`, and
   `npm run demo -- --check --executor <your-executor>`. On Windows use
   `npm.cmd` where PowerShell requires it. A passive preflight is not a live
   authentication or model test.
5. Load the v0.9.1 browser companion from its new directory or manually install
   the optional Web Bridge 0.9.6 file, as appropriate for your existing setup.
   Check the displayed version and preserved local settings. Portal auto-update
   remains separate as described above.
6. Start the new service and perform the target-platform, browser, continuation,
   and provider tests you intend to run. Change any existing startup shortcut
   to the new directory only after your manual checks pass. Retain the old
   installation and private backup until you are satisfied with the upgrade.

## Rollback

Stop v0.9.1 before switching back. Keep any new task evidence and workspace edits
in a separate private backup first. Point the service or startup shortcut back
to the retained v0.9.0 installation and restore its pre-upgrade configuration
and state snapshot together if necessary. Do not overwrite current project
workspaces with old backups or assume state written by the newer version is
backward-compatible. Reload the previously installed browser companion or
userscript when rolling back that component. Keep the two installations
side-by-side and run only the selected version against the original state.

## Unchanged boundaries

This release does not alter the license, notice, provider-neutral architecture,
or shipped default configuration. ACP remains a loopback, single-user control
plane. Each executor uses its configured account, permissions, and quota.
